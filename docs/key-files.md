# Key files (load-bearing)

Detailed inventory of the project's load-bearing files. Read this when starting a non-trivial task; the top-level `CLAUDE.md` only carries the summary architecture and points here for the file-by-file map.

## Core (load-bearing contracts)

- `src/core/types.ts` — `CipherSpec`, `StepNode`, `State` variants, `TraceFrame`, `StepDocumentation`. Saved JSON references these shapes forever; changes here are breaking.
- `src/core/runtime.ts` — the walk-and-trace engine. Pure given a registry.
- `src/core/registry.ts` — `StepRegistry`. Maps stepType → `{ executor, doc }`.
- `src/core/spec-mutations.ts` — `findStep`, `findStepAndParent` (Slice 4: returns `{ node, parent, indexInParent } | null` for ANY node kind — leaves AND groups AND iterates — so the visual editor can anchor inserts to groups), `updateStepParams`, `updateAllStepsByType`, `insertStepAfter`/`insertStepBefore`/`removeStep`/`reorderStep` (Slice 4 structural mutators; pure, reference-equality preserved on untouched branches, throw on missing anchor id; reorder is intra-parent only — cross-parent moves are `removeStep + insertStepAfter`), `compareSpecs`. Pure spec-in/spec-out. `compareSpecs` returns `SpecParamDiff[]` where each entry optionally carries `scalar` (before/after for primitive params) or `cells` (per-cell `ParamCellDiff`, 1D index or 2D row/col; flat-256 arrays auto-decompose to 16×16 like the S-box editor). Bare diffs with neither field intentionally pass through — `describeDelta` falls back to "X changed" for them.
- `src/core/format.ts` — `ByteFormat`, `formatByte`/`parseByte`/`formatBytes`/`parseBytes`/`parseBytesWithLength`. Consumed by every byte-rendering site.
- `src/core/spec-shapes.ts` — Static state-shape inference for a `CipherSpec`, added alongside the `shapeContract` field on `StepDocumentation`. Exports `inferShapesAtAnchors(spec, registry): ReadonlyMap<string, StateShape>` (returns the shape that exists immediately after each leaf/container completes; consumed by `GraphView` to decorate every `data-drop-anchor` element with a `data-state-shape` attribute) and `validateShapes(spec, registry): GraphWarning[]` (emits `state-shape-mismatch` for every leaf whose declared contract input disagrees with the inferred upstream shape — trace-free, fires before Run). Both share one walker that threads shape through groups (transparent — DFS through, children inherit parent shape) and iterates (opaque — body always starts in `matrix4x4-bytes` per the runtime's `state = blocks[i]` substitution; exit shape is `matrix4x4-bytes` regardless of what surrounded the iterate). `"any"` and missing-contract leaves skip validation and pass shape through. Used by `GraphView`'s `rawWarnings` memo (concatenated with `validateGraph`'s trace-derived output) and by the `shapesByAnchor` memo that powers the drop-anchor greying CSS rules. Pure function; same inputs → same outputs.
- `src/core/graph.ts` — `deriveAuxGraph(trace, spec): CipherGraph` plus `GraphNode` / `ContainerNode` / `GraphEdge` / `EdgeKind` types. **Slice 9 added `validateGraph(graph, trace): GraphWarning[]`** — pure structural analysis over the (graph, trace) pair. Four warning kinds in a discriminated union: `"orphaned-read"` (a step requested an aux key with no upstream producer — sourced from `frame.auxReadMissing`, which the runtime started populating in the same slice), `"unused-write"` (a frame wrote an aux key that no later frame reads — diffed against the producer-set of `graph.edges`), `"cycle"` (DFS over aux + state edges; acyclic by construction for any trace-derived graph, kept as defense-in-depth for future non-trace-synthesized edges), and **`"state-shape-mismatch"`** (a leaf's declared `shapeContract.input` disagrees with the spec-inferred upstream shape — produced by `validateShapes` in `core/spec-shapes.ts`, concatenated into the warning list in `GraphView`'s `rawWarnings` memo; trace-free, fires the moment an incompatible step is dropped). All warnings carry the *canonical* (post `:b{i}` strip) stepId, deduped so multi-block iterates don't repeat the same logical issue N times. Today's shipped strict consumers (e.g. `add-round-key`) throw on missing aux rather than emit a frame, so orphan warnings won't trigger naturally until Slice 10's graceful aux primitives (`aux-xor`, `aux-copy`, `aux-load`) land — the validation plumbing is in place now so the visual editor can flag wiring problems as soon as those steps go in. The signature deviates slightly from the plan's `validateGraph(graph)`: the trace is needed for orphaned-read detection (the graph deliberately stores only realized edges, not unfulfilled-read requests), and splitting it out keeps the graph itself a clean "what happened" snapshot. Pure function combining two passes. **Aux pass (trace-derived)**: nodes/containers/`rootIds` from spec walk; edges from `auxRead`/`auxWritten` plus iterate-mediated synthesis (`split-blocks → iterate → concat-blocks`, since the runtime moves those aux values itself without recording them in any frame's `auxWrites`); `blockSpan` annotations on iterate-body nodes from `frame.blockIndex`. Strips `:b{i}` per-iteration suffixes during edge dedup (so 4-block ECB collapses to one logical edge per consumer, not four). **State pass (spec-derived, commit 2 of the graph-readability sequence)**: `inferStateEdges(spec)` emits one `kind: "state"` edge per DFS-consecutive pair of sibling leaves within each iterate-scope. Groups are TRANSPARENT (DFS through; the spine crosses `round.k → round.k+1` boundaries — the pedagogical headline); iterates are OPAQUE (their body is its own scope, no spine edge crosses the boundary in either direction, matching the runtime's `state = cloneState(blocks[i])` + `aux[outBlocksAux]` accumulation semantics — drawing a state edge across the iterate would double the aux edges that already capture the per-block handoff honestly). State edges carry the sentinel `auxKey: "state"`, distinguishable from real aux keys; trace-derived edges are appended first, state edges last. Since state inference reads only the spec, the spine appears pre-run on the structural skeleton — the user sees what the cipher does the moment they load it. **Feistel future**: when a Feistel-style cipher (branching state via left/right halves) lands, the "DFS-consecutive leaves share state" assumption breaks; this pass needs revisiting along with any runtime-recorded lineage. **Slice 6 added `collapseGraph(graph, collapsedIds): CipherGraph`** — a pure view-time transform that runs AFTER `deriveAuxGraph`. Per the advisor: kept SEPARATE (not folded into derivation) so Slice 1's "graph is pure (spec, trace)" contract survives. Semantics: collapsed containers stay in `containers` (renderer draws them as chips) with `childIds: []`; leaves/containers under any collapsed ancestor disappear; edges' endpoints get remapped to the outermost collapsed ancestor on each endpoint's path; self-loops produced by remap are dropped; survivors dedup by `(kind, from, to, auxKey)` so the `kind`-defensive dedup key from commit 1 keeps state and aux edges with the same endpoints distinguishable. `rootIds` is filtered to still-resolvable ids. Empty `collapsedIds` short-circuits with reference equality. **Commit 4 of the graph-readability sequence added `replicateHighFanoutSources(graph, threshold, modes?): CipherGraph`** — a pure view-time transform that runs AFTER `collapseGraph`. Sources with `> threshold` outgoing `kind: "aux"` edges (counts state edges as zero — they're 1-to-1) get a replica node inserted next to each consumer, with edges rewritten to flow from the replica. Replica id: `${src}@->${consumer}`. Replicas carry `replicaOf` pointing at the source's canonical stepId so click handlers can scrub to the source's trace frame. Original source nodes stay in `nodes` (linear-list click-to-scrub keeps working). One replica per (source, consumer) pair, even when multiple aux keys flow the same direction — the (1+N) tiny edges still beat (1) long edge. Layout: replicas inherit the consumer's `containerPath`, then are spliced into the parent container's `childIds` (or `rootIds` if root) immediately before the consumer. **Commit 5 added per-source overrides via the optional third `modes` argument** (`{ [sourceId]: "always" | "never" }`): `"always"` forces replication regardless of fanout count, `"never"` suppresses it even when the source's count exceeds the threshold. Absence of an entry is the implicit `"auto"` default (defer to the threshold). The transform itself honors `"always"` even when `threshold <= 0` so unit tests can drive it in isolation; the GraphView enforces the master-switch semantic ("global off = no replicas regardless of overrides") by short-circuiting the call entirely when the toolbar checkbox is off. `threshold <= 0` with no `"always"` overrides AND "no source over threshold" both short-circuit with reference equality. Slice 1 + Slice 6 of the 2D editor plan; commits 1, 2, 4, and 5 of the graph-readability sequence.
- `src/core/document.ts` — `CipherDocument` file format wrapper + `serializeDocument(doc): string` (stable key order — alphabetical at every level; arrays preserve order) + `parseDocument(text): { ok: true, doc } | { ok: false, error }`. Hand-written TS types so optional fields are `field?: T` rather than Zod's inferred `field?: T | undefined` (matters under `exactOptionalPropertyTypes`). The wrapper holds a required `spec: CipherSpec` plus three optional sidecars: `layout?: LayoutSpec` (graph positions, collapsed groups, flow direction), `session?: SessionSnapshot` (mode + cipher + cipherMode + padding + byteFormat + optional inputBytes/keyBytes), `metadata?: DocumentMetadata` (name, createdAt, appVersion). `schemaVersion: 1` is the migration anchor — a pre-check in `parseDocument` gives a friendly forward/back-compat error for any other numeric version before the full Zod schema runs. Slice 3 of the 2D editor plan; unblocks Slice 5 (save/load UI) and Slice 7 (URL share).
- `src/core/document-schema.ts` — Zod schemas backing `document.ts`. Strictness split: wrapper layers (CipherDocument / LayoutSpec / SessionSnapshot / DocumentMetadata) are `.strict()` so unknown fields force a schemaVersion bump; CipherSpec + StepNode stay loose so per-step extensions can land without forcing a migration. StepNode uses `z.discriminatedUnion("kind", [StepLeafSchema, StepGroupSchema, IterateGroupSchema])` for pinpoint error paths; recursion lives in the `children` fields via `z.lazy(() => StepNodeSchema)` so each per-kind ZodObject keeps its concrete type and satisfies `z.discriminatedUnion`'s per-option constraint without casts. Also exports `CIPHER_IDS` / `CIPHER_MODES` / `PADDING_SCHEMES` / `BYTE_FORMATS` value tuples (mirrored from `ui/stores/*` via type-only imports + `satisfies readonly Cipher[]` bottom check + `Exclude<...>` top check) so adding a new variant to those unions surfaces here at `tsc` time.
- `src/version.ts` — `APP_VERSION: string` re-exported from `package.json` (via `import pkg from "../package.json" with { type: "json" }`; works under `resolveJsonModule: true` + `verbatimModuleSyntax: true`). Single source of truth so a release bump is a one-file edit. Consumed by the App-shell footer (informational) and by `buildSaveText` in `App.tsx` to stamp `metadata.appVersion` into exported documents on the session-on branch only (spec-only saves remain byte-stable so the planned URL-share invariant survives). See `docs/versioning.md` for the release process.

## Ciphers

- `src/ciphers/default-registry.ts` — wires every step type. Adding a new step means editing this.
- `src/ciphers/aes-128.ts`, `src/ciphers/aes-128-decrypt.ts` — AES-128 forward + inverse specs.
- `src/ciphers/aes-192.ts`, `src/ciphers/aes-192-decrypt.ts` — AES-192 (Nk=6, Nr=12). Reuses every AES-128 step type; only `ROUNDS` and `inputs.key.byteLength` differ.
- `src/ciphers/aes-256.ts`, `src/ciphers/aes-256-decrypt.ts` — AES-256 (Nk=8, Nr=14). Same shape as AES-192; the `aes.key-expansion@1` step has an Nk>6 branch that fires only here.
- `src/ciphers/aes-constants.ts` — AES_SBOX, AES_INV_SBOX, AES_RCON, AES_MIX_MATRIX, AES_INV_MIX_MATRIX, AES_SHIFT_ROWS, AES_INV_SHIFT_ROWS. Rcon table is long enough for all three key sizes.
- `src/ciphers/aes-round-builder.ts` — extracted forward/inverse AES round body (`buildAesEncryptBody(rounds)` and `buildAesDecryptBody(rounds)`). Used by single-block `aes-128.ts` and the multi-block ECB factory; CBC/CTR factories will call it too when Phase 2/3 land. The single point of truth for the per-block round-group construction.
- `src/ciphers/aes-ecb-builder.ts` + `aes-128-ecb.ts` + `aes-128-ecb-decrypt.ts` — Phase 1 multi-block ECB. The builder is variant-aware (`aes-128`/`192`/`256` × `encrypt`/`decrypt`) but only the AES-128 spec files exist today; AES-192/256 ECB are a one-line spec each, waiting on Phase 4. The spec shape is `[key-expansion, split-blocks, compute-block-count, iterate{...round-body...}, concat-blocks]`; `applyPaddingScheme` prepends `pkcs7-pad` (or sibling) on encrypt and appends `pkcs7-unpad` on decrypt around the outside.
- `src/ciphers/speck-32-64-builder.ts` + `speck-32-64-{be,le}{,-decrypt}.ts` — Speck32/64 spec factory + four canonical specs (BE encrypt, BE decrypt, LE encrypt, LE decrypt). The four files differ only by the `(byteOrder, direction)` pair passed to the builder; the builder bakes the per-leaf params and the decrypt round-key reversal. Block size is 4 bytes, key is 8 bytes, 22 rounds, no padding overlay support.
- `src/ciphers/serpent-spec-builder.ts` + `serpent-round-builder.ts` + `serpent-{128,192,256}{,-decrypt}.ts` — Serpent SP-network spec factory + six canonical specs (all three key sizes × encrypt/decrypt). The six files differ only by the `(keyByteLength, direction)` pair passed to `buildSerpentSpec`; the round body is identical across all three variants because Serpent internally pads shorter keys to 256 bits as a key-schedule preamble. Block size 16 bytes, 32 rounds, single-block only today (multi-block ECB/CBC/CTR is a future phase that will plug into the existing `iterate` primitive the same way AES-128-ECB does). The cipher runs in **standard form** (visible IP/FP, per-nibble S-box, table-based LT) — the equivalent bitslice form (no IP/FP, column-wise S-box, word-equation LT) is mathematically the same but pedagogically opaque.
- `src/ciphers/serpent-constants.ts` — SERPENT_SBOXES (8 forward), SERPENT_INV_SBOXES (computed from forwards at module load), SERPENT_IP, SERPENT_FP (128-entry bit permutations, mutual inverses), SERPENT_LT_TABLE, SERPENT_INV_LT_TABLE (128 entries each, where `LT_TABLE[i]` lists the input bit positions whose XOR yields output bit `i`), SERPENT_PHI = 0x9e3779b9 (key-schedule constant), SERPENT_ROUNDS = 32, SERPENT_BLOCK_BYTES = 16. Bit-numbering convention is LSB-first within bytes everywhere.

## UI stores (singletons; module-scope signals on purpose)

- `src/ui/stores/trace.ts` — current trace + frame index, `setTrace` preserves focus by stepId across re-runs.
- `src/ui/stores/format.ts` — active byte format, persisted in `localStorage`.
- `src/ui/stores/spec.ts` — current spec + (cipher, cipherMode, mode) selector. `defaults` is a **3D** `Record<Cipher, Partial<Record<CipherMode, Record<Mode, CipherSpec>>>>` table — each cipher's inner record only carries the modes-of-operation it supports (Speck has only `single-block`; AES-128 has `single-block` + `ecb` today). `resolveDefault` falls back to `single-block` when the requested cipherMode isn't registered, so picking ECB on AES-128 and then flipping to Speck just lands you back on single-block Speck without crashing. `setMode`, `setCipher`, `setCipherMode`, `resetSpec`, and `setPadding` all funnel through `applyPaddingScheme` so the active padding scheme survives every selector flip. `setSpecFromDocument(doc)` (Slice 5) is the **Load boundary** — it bypasses the public setters' spec-rebuilds (each would overwrite the doc's literal spec with the canonical default for the new selectors) and lands stores in hydration order: byteFormat first (so a later format of restored bytes uses the new format), then cipher/cipherMode/padding/mode via the raw signal setters, then `setSpec(doc.spec)` directly. Cross-store consistency is NOT corrected — the document's spec is authoritative; an inconsistent (cipher, cipherMode) combo just greys out the dropdown but still runs. **Slice 8 added `insertStepIntoSpec(stepType, anchor)`** — the boundary GraphView's drop handler calls. Two anchor flavors: `{kind:"after", stepId}` routes through `insertStepAfter` (works for leaf or container anchors thanks to Slice 4's `findStepAndParent`); `{kind:"root-append"}` rebuilds `spec.steps` directly so the empty-canvas / empty-spec edge case stays uniform. Id generation is a `<lastStepTypeSegment-without-@N>-<n>` walker that scans every node (leaf + group + iterate) for collisions before incrementing — `generic.byte-substitution@1` → `byte-substitution-1`, `byte-substitution-2`, … Returns the generated id so callers can route trace focus once the auto-rerun lands (even if that frame is the expected error frame for a leaf with `params: {}`).
- `src/ui/stores/cipher.ts` — active AES variant (`aes-128` / `aes-192` / `aes-256`), persisted in `localStorage`. Also exports `DEFAULT_KEY_BYTES_BY_CIPHER` (FIPS-197 §A.1/§A.2/§A.3 canonical keys) used by the App's cipher-change handler to swap the key field only when it still holds the previous cipher's default.
- `src/ui/stores/cipher-mode.ts` — block-cipher mode of operation (`single-block` / `ecb` / `cbc` / `ctr`), persisted in `localStorage`. Two related constants: `SUPPORTED_CIPHER_MODES` is the *globally* shipped set (Phase 1: `single-block`, `ecb`); `SUPPORTED_CIPHER_MODES_BY_CIPHER` is the **per-cipher matrix** that says which (cipher, cipherMode) combinations have an actual spec wired up in `stores/spec.ts`'s defaults table (Phase 1: only `aes-128` × `ecb`; everything else is single-block only). The matrix is consulted by `isCipherModeSupported` from both the App's dropdown (to disable unsupported combos in the option list) and `setCipher` in `spec.ts` (to reset `cipherMode` to single-block when the user switches to a cipher that doesn't support the active mode). `loadInitial` runs the same check at boot so a persisted cross-store mismatch (e.g. `cipher=aes-192, cipherMode=ecb` in localStorage from before AES-192-ECB ships) gets self-corrected on next reload.
- `src/ui/stores/history.ts` — 5-deep run snapshot ring buffer + `pushSnapshot` (auto-dedups identical re-runs), `findPreviousRunFrameByStepId`, and the `showPreviousRun` overlay toggle.
- `src/ui/stores/padding.ts` — active padding scheme (`none` / `pkcs7` / `zero-pad` / `iso7816-4`), persisted in `localStorage`. `paddingLimits(mode, scheme, cipher, cipherMode?)` returns the allowed raw-input byte-length range so the Run handler can produce friendly errors. Cipher-mode is a fourth arg with a `"single-block"` default — multi-block ECB/CBC widen the range to `MAX_BLOCKS_UI × 16` (16 blocks = 256 bytes today), CTR uses the same cap but skips padding, single-block keeps today's 0..15 / 1..16 / 16..16 ranges per scheme. The cap is a UI guard (trace browsability), not a runtime limit — bump the `MAX_BLOCKS_UI` constant to encrypt a paragraph at the cost of a noisier scrubber.
- `src/ui/stores/auto-rerun.ts` — two signals: `autoRerun` (user preference, persisted in `localStorage`, default true) and `dirty` (session-only flag set when manual mode receives a spec edit). The App's `createEffect(on(spec, ...))` branches on `autoRerun()` — true keeps the 200ms debounced re-run; false just calls `setDirty(true)` so the inline "edits pending" banner appears. Flipping `autoRerun` back ON clears `dirty` so the banner doesn't go stale.
- `src/ui/stores/view-mode.ts` — three-mode signal (`linear` / `graph` / `json`), persisted in `localStorage`. Drives the tab bar above `.trace-view`: linear shows today's per-frame view (frame header, StepStrip, BlockBadge, FrameStateView, StepDescription, ParamEditor); graph swaps in `GraphView`; json swaps in a `<pre>` of `JSON.stringify(spec(), null, 2)`. Slice 2 of the 2D editor plan.
- `src/ui/stores/view-replication.ts` — boolean signal (`replicationEnabled`, persisted as `cryptographer.replicationEnabled`, default false). When true, GraphView pipes the collapsed graph through `replicateHighFanoutSources(graph, REPLICATION_THRESHOLD, modes)`. The threshold is exported as a constant (= 6); commit 5 wired the modes argument up from the layout store's `replicationModes`. Off by default because the "one source, many edges" view of a key schedule is also legitimately pedagogical; user opts in via the graph toolbar checkbox. **Master-switch semantic**: when the toggle is OFF, GraphView skips the transform entirely — per-source `"always"` overrides in `LayoutSpec.replicationModes` only fire when the global toggle is ON. Commit 4 of the graph-readability sequence.
- `src/ui/stores/view-density.ts` — three-preset signal (`compact` / `normal` / `spacious`), persisted in `localStorage`. Default `normal` = 1.0× exactly, so the pre-density layout is byte-stable. Exports `DENSITY_SCALE` (compact 0.75× / normal 1.0× / spacious 1.25×) as the single source of truth for the scale factor. `GraphView`'s `layoutConstantsFor(density)` builds a `LayoutConstants` record (`LEAF_W`, `LEAF_H`, `STACK_GAP`, `FLOW_GAP`, `CONTAINER_PAD`) by multiplying the base constants by `DENSITY_SCALE[density]` and rounding to integer pixels; `layoutNode` / `layoutRoot` / `labelTextLength` take this record so they remain pure (testable without rendering) and re-run automatically on density flips via the `createMemo` chain inside `GraphView`. Density lives in its own store (not in `LayoutSpec`) because it's a viewer preference, not a document fact — a shared `.cipher.json` renders at whatever density the reader prefers, and the Slice 5 byte-stability property is preserved unconditionally. Commit 3 of the graph-readability sequence.
- `src/ui/stores/url-share.ts` — 2D editor Slice 7. Exports `encodeDocumentToHash(doc): Promise<string>` and `decodeHashToDocument(hash): Promise<{ok:true,doc}|{ok:false,error}>` plus the `HASH_PREFIX = "doc="` constant and the `buildShareHash` / `extractHashPayload` helpers. Pipeline is `serializeDocument → UTF-8 → CompressionStream("deflate-raw") → base64url`; measured payload sizes: AES-128 spec-only 1.6 KB, AES-256 + session worst case 1.9 KB (raw JSON would have been ~21 KB; plain base64 ~28 KB). **Decision pinned by measurement, not preference** — pako would have added ~12 KB bundle for the same ratio; CompressionStream is platform-native (Chrome 80+, Firefox 113+, Safari 16.4+, Node 21+ as a global) so the dependency is zero. Three non-obvious correctness pieces locked in by tests: (1) **writer-side rejection swallow** — `CompressionStream`'s writer's `write`/`close` promises reject independently of the readable side; without `.catch(() => {})` on each, Node treats them as unhandled even when the readable rejection is caught downstream. (2) **portable streaming form** — feeds bytes through the writer interface instead of `new Blob([bytes]).stream().pipeThrough(...)` because jsdom 29's Blob lacks `.stream()`; production + test paths stay identical. (3) **`deflate-raw` over `gzip`** because gzip's header + CRC32 footer (~18 bytes) matters at this size class. App-side wiring: the `[share…]` button calls `shareDocument` (async; honors the `includeSession` toggle the same way Save does), writes the encoded URL to `navigator.clipboard.writeText`, falls back to placing the URL in the address bar via `replaceState` if clipboard is blocked. Boot decode runs in App's `onMount` — reads `window.location.hash`, routes through the shared `applyDocument` boundary (factored out of `handleLoadFromText` so file-load and URL-load both go through one path), strips the hash on success via `replaceState` so refresh doesn't re-apply. Failure preserves the hash for forensic value.
- `src/ui/stores/layout.ts` — per-spec.id `LayoutMap` (`{ [specId]: LayoutSpec }`), persisted as one JSON blob under `cryptographer.layouts`. Mirrors the existing `format.ts` template: defensive `loadInitial` (missing localStorage → empty map; corrupted JSON → empty; non-LayoutSpec values silently dropped via lightweight `isLayoutSpec` shape check); `useLayoutMap()` for reactive reads; `getLayoutForSpec(id)` for non-reactive snapshots. Writes funnel through `setNodePosition(specId, nodeId, x, y)`, `toggleCollapse(specId, containerId)`, **`setReplicationMode(specId, sourceId, mode | null)` (commit 5 of the graph-readability sequence — `null` clears the override back to implicit auto)**, and the Load boundary `setLayoutForSpec(specId, layout)` — which removes the entry when given `null` OR an empty layout (`!hasUserLayout`). The empty-layout removal is the byte-stability gate Slice 5's spec-only-save test depends on (an always-present empty sidecar would defeat URL-share determinism). `hasUserLayout(l)` returns true iff at least one pinned position, one collapsed container, OR one `replicationModes` entry is present; App's `buildSaveText` gates `doc.layout` inclusion on it. Empty `replicationModes` maps are NOT preserved on the LayoutSpec (the internal `withReplicationModes` helper drops the field when empty so a serialized layout never carries `"replicationModes":{}` — that would differ byte-for-byte from absence and break the gate). NO pruning of stale stepIds — if a future spec mutator deletes a step that has a pinned position or replication override, the entry sits unused in localStorage indefinitely (renderer skips dangling refs; storage is cheap; pruning is risk surface for a Slice 8 follow-up). Slice 6 of the 2D editor plan; commits 4–5 of the graph-readability sequence extended it.

## UI components

- `src/ui/components/ByteCellInput.tsx` — format-aware editable byte cell. Width adapts (hex=2/dec=3/ASCII=4 chars). Used by SboxEditor (16x16) and MatrixEditor (4x4).
- `src/ui/components/BytesView.tsx` — variable-length sibling to MatrixView. Renders BytesState frames (pkcs7-pad / pkcs7-unpad) as a 1×N wrapping row with length-delta "missing" cell placeholders when the row's compareTo side is longer. When the longer side of a row pair exceeds 16 bytes (i.e. the frame is multi-block), cells are visually segmented into per-block `.bytes-block-group` panels with "Block N" headers; each panel is a **4×4 grid with `grid-auto-flow: column`** so the byte ordering matches the AES State matrix the reader has been watching inside the round (byte[0..3] fill column 0 top-to-bottom, etc — FIPS-197 §3.4). This makes ECB-mode repetition obvious: identical plaintext blocks become identical-looking 4×4 ciphertext blocks side-by-side. Single-block frames (max length ≤16) keep the flat layout. The same grouping is mirrored in App's `SingleStateView` for mixed-shape frames (notably `concat-blocks`, where the bytes side is N×16 long).
- `src/ui/components/BlockBadge.tsx` — small "Block i of N" chip rendered above the per-frame state view when the current frame belongs to an iterate loop (i.e. `frame.blockIndex !== undefined` and the trace has more than one block). Pure visual — no scrubber surgery. Driven by App-level `blockCount` memo that scans `trace.frames` for the max `blockIndex`.
- `src/ui/components/RunExplorerModal.tsx` — side-by-side run comparison modal (uses native `<dialog>` for backdrop + escape handling). Pure delta-string formatter lives in `run-delta-format.ts` so node-env tests can pin its output without spinning up jsdom.
- `src/ui/components/StepPalette.tsx` — 2D editor Slice 8: left sidebar inside `.graph-view-layout` listing every non-padding registered step type, grouped by namespace (`aes` / `generic` / `speck` / `serpent`, in `GROUP_ORDER`; unknown namespaces tail-append alphabetically). Each entry is `draggable={true}` and on `dragstart` writes the step type onto `dataTransfer` under both the project-private `STEP_TYPE_DRAG_MIME` (`application/x-cryptographer-step-type`) and `text/plain` (cross-browser fallback). Excludes `PADDING_STEP_TYPES` from `core/spec-mutations.ts` — palette-dropping a padding overlay step type would create a top-level leaf that the next padding-selector flip silently strips via `stripPaddingLeaves`, so surfacing those types as palette entries would be a stealth footgun. Entries within a group sort alphabetically by display name (from `StepDocumentation.name`, falling back to the type id for doc-less registrations). Each `<li>` carries `data-step-type=<typeId>` + `data-testid="step-palette-entry-<typeId>"` so tests can target by registry key.
- `src/ui/components/GraphView.tsx` — SVG renderer over `deriveAuxGraph(getTrace(), spec())` followed by `collapseGraph(graph, collapsedSet)` as a view-time transform. Hand-rolled FIPS-197-flavored layout: top-level and iterate bodies flow LEFT-TO-RIGHT (time rightward), groups stack their children VERTICALLY. Iterates carry a `×N` chip in the header when `blockSpan > 1`. Edges are bezier curves with geometry-driven exit/entry sides: vertical sides (bottom→top) when boxes overlap on x but not y (intra-group siblings like AES's sub-bytes → shift-rows), horizontal sides (right→left) for everything else (root flow, iterate bodies, cross-container fan-outs). Inset + pull are clamped to half the natural gap so STACK_GAP=6 siblings get a clean monotonic line. The auxKey lives in a hover `<title>`. Clicking a leaf calls `setFrame(idx)` for the first trace frame whose canonical (`:b{i}`-stripped) stepId matches. **Slice 6 added container drag + collapse.** Container headers carry a transparent drag-handle band (`onPointerDown` → window-level `pointermove`/`pointerup` listeners; `setPointerCapture` is best-effort and jsdom-tolerant). Click-vs-drag disambiguation uses a 4px movement threshold — sub-threshold pointerups commit no position. The chevron `<g>` on the right side of the header toggles `collapsedGroups` for that container; clicking again restores. Pinned root-level entries do NOT advance the auto-layout cursor (so dragging round.5 doesn't push 6–10 sideways); canvas dimensions track max-right/max-bottom across pinned + un-pinned boxes so the SVG grows to fit anywhere you drag a container. **Slice 8 layered palette drops on top.** The outer wrapper is now `.graph-view-layout` (flex row: palette on the left, scroll wrapper on the right). The scroll wrapper carries `onDragOver`/`onDragLeave`/`onDrop`; `dragover` accepts only payloads that carry the project's `application/x-cryptographer-step-type` MIME (or `text/plain` as a cross-browser fallback) and toggles `.graph-drop-zone-active` for the dashed-outline highlight. `LeafRect` and `ContainerRect` carry `data-drop-anchor=<stepId>` on their outer `<g>`; the drop handler walks up via `closest("[data-drop-anchor]")` from the event target to find the anchor. Three anchor flavors: drop on a leaf → `insertStepAfter(leafStepId)`; drop on a container's outer `<g>` → `insertStepAfter(containerId)` (which places the new leaf AFTER the container in its parent, NOT into the container body — explicit Slice 8 semantic, since `insertStepAfter` is the only mutator Slice 4 shipped and "into-container" would have needed a separate helper); drop on the SVG background (no anchor) → root-append via `insertStepIntoSpec(..., {kind:"root-append"})`. Replica leaf nodes (`graph-leaf-replica`) carry `data-drop-anchor={clickTargetId}` — the SOURCE's real stepId, not the synthetic `${src}@->${consumer}` replica id — so a drop on a replica lands the new step after the source. Leaf-level drag is still NOT enabled (the Slice 6 deferral); palette-dropped leaves take their starting coordinates from auto-layout, not from the drop pixel.
